# 阶段1：今日对话与内部工具循环

日期：2026-11-05；版本：0.2.0-alpha.1；分支：feature/planning-agent。

## 已实现

- 原生Function Calling循环：千问请求工具，主进程执行并回传关联tool_call_id，模型继续决策；本阶段不使用MCP或JSON动作回退。
- 今日对话：查询、按需澄清、评分调整草案、用户确认/放弃、运行中停止、工具执行记录。
- 工具：list_tasks、get_task、propose_priority_change、ask_user、finish_reply。最后两个用于明确等待/结束状态，不能以普通文本猜测状态。
- 对话、模型消息、工具观察、待确认草案和执行记录存入SQLite；重开恢复最近对话。中断的running标为failed并移除悬空工具消息，可继续交流，不静默重放写入。
- 评分写入：仅可信UI确认可调用，检查原updatedAt和原评分，短事务同时修改任务并记录幂等操作；变化的任务拒绝覆盖，重复确认不重复写。
- 每执行片段最多6次模型决策/12次工具，120秒总预算、单请求30秒；整段对话最多24次决策，过长上下文停止并提示新建。
- 新版独立数据目录，不直接使用0.1用户数据库；主进程持有数据库与模型客户端。

## 基础修复

1. isOverdue读取task.dueAt，消除有截止任务时今日页异常。
2. updateTask区分user/review，自动重评不触发人工锁；调用返回前复核任务是否被用户修改。
3. 修复“明天/后天几点”的非法时间参数，支持下午与分钟并拒绝超范围时间。
4. 修复原有TypeScript路径/空值/标签只读类型问题，增加sqlite类型与vue-tsc，使主进程和Vue类型检查可执行。

## 你可以怎样体验

在仓库根目录安装依赖后运行`npm run build`，双击start-plan.bat（或开发时npm run dev）。在新版设置里填写支持原生工具调用的模型；本机验证使用qwen-plus。新版密钥和任务不会自动沿用旧软件。

先用顶部输入框录入两三个任务，等分析完成，再在“今日助理”输入：

1. “看看我有哪些未完成任务。”
2. “把课程报告的重要度改成5。”
3. “把报告优先级提高一些。”（准备多个报告任务，观察是否先查询或澄清）

修改草案不会直接写入；确认后任务评分与排序刷新。待回答问题可继续输入，未确认草案需先确认或放弃。新对话保留旧库记录，但完整历史会话选择界面本阶段尚未实现，默认只恢复最近会话。

本阶段**未实现**：自然语言改期/创建事项、长期记忆/RAG、课表/时段调度、后台完成追问、通知红点、作业/OCR。现有0.1“推迟明天”按钮仍使用旧日期语义，不把它当新调度功能。模型不能使用不存在的工具完成这些请求。

## 文件与调用链

```text
AgentChat.vue → window.api.agentStart/Send → preload → AGENT_IPC
→ runner.ts → model.ts（发送原生tools）
← tool_calls → tools.ts白名单/参数检查
→ taskDao/getDb → SQLite → role:tool观察 → 下一次模型决策
→ ask_user / finish_reply / 评分草案
→ UI确认 → applyPriorityChange短事务 → 广播刷新
```

- shared/agent.ts：Run状态、事件、草案、IPC通道。
- main/agent/model.ts：原生tool_calls解析、超时和HTTP错误；不输出服务端原始错误正文或凭据。
- main/agent/tools.ts：工具定义、运行时校验、查询/草案、可信确认的事务与幂等。
- main/agent/store.ts：Run/消息/事件持久化及中断恢复。
- main/agent/runner.ts：模型循环、等待/结束、取消、预算、确认与广播。
- db/migrations.ts：v6添加agent_runs、agent_events、agent_actions；0.1业务表不在本阶段强制改为新计划语义。

## 验证与真实失败记录

`npm run typecheck`：主进程TypeScript和Vue检查通过。`npm test`：19项隔离库自动化通过，含预算停止、未知/非法参数、读取后草案、确认前不写、重复确认、同对话多次修改、并发版本、事务故障回滚、暂停恢复、取消与迟到响应、协议纠正。

真实qwen-plus场景：查询并回传真实DAO结果；生成评分草案并确认后写入；模糊指代提出澄清。最终`npm test -- --live`共22项通过（19项自动化加3项真实场景）。均使用临时测试任务，未发送用户原始个人库。该记录不是大规模成功率评测。

真实测试曾出现：模型以普通文字提问但未调用ask_user，被误标为completed。已加入finish_reply和明确终态协议；普通文本最多要求一次协议纠正，仍不合规则停止。修复后上述三场景通过，保留这一失败作为Harness设计依据。

原生窗口检查：使用独立演示库，今日正常显示带截止任务；发送“把课程报告初稿的重要度改成5”，模型依次查任务/读详情/提出草案；确认前评分3，确认后5，综合分59→81并自动排序到前方。关闭重开后对话记录和评分仍在。桌面验证使用合成任务；原0.1窗口与用户库保留。
