# 阶段2：课表约束下的具体执行计划

日期：2026-11-05；版本：0.2.0-alpha.2；分支：feature/planning-agent。

## 实际能力与使用顺序

1. 在“全部”或“今日”的任务卡打开“时间设置”，核对截止和预计耗时；截止留空表示没有硬性截止。
2. 到“日程”设置每天可安排窗口、任务分钟上限与任务间休息；逐条录入课程/固定事件的星期、开始/结束、生效日期。
3. 使用日程的任务选择与试排按钮，或在今日助理中说“把课程报告安排到明天下午，避开课表”。
4. 核对预览中的新安排、原安排和未安排项。确认后执行块才保存，今日和周视图刷新。
5. 可以锁定执行块以免自动重排；移除安排仅移除时段，不删除任务或修改截止。

日程为横向七日、纵向时间的周表；今日显示当天按时序横向排列的课程/任务卡片。本阶段今日卡片尚非按分钟等比例绘制的完整时间轴。

## 数据与旧记录处理

迁移v7新增deadline_at、deadline_confirmed、deadline_source，以及calendar_courses、planning_settings、plan_blocks、plan_previews、planning_events。

- Task.deadlineAt：截止候选或已确认截止；deadlineConfirmed表明是否已确认。
- Task.dueAt：仅为旧评分/展示接口的兼容别名，映射已确认的deadlineAt，绝不代表执行时间。
- Task.legacyDueAt：原due_at原样保留作历史核对，不直接用于新版调度。
- plan_blocks：独立保存task_id、epoch毫秒开始/结束、锁定、安排原因；一个任务当前只支持一个连续块。

旧due_at混合截止与旧自动排期，不能可靠反推来源。迁移保留原值，把非空旧日期标为待确认，不擅自转成截止或执行块。新模型/规则提取的日期也先作为候选；用户在时间设置中确认后才成为硬约束。解析结果没有日期的任务可按用户选择窗口排期，不伪造截止。

打开旧版数据库前，使用VACUUM INTO生成plan.db.before-v7-时间戳.db一致性备份（含WAL可见数据），失败时不继续迁移。v7 DDL在事务中执行。迁移可重复，备份和数据库均不入Git。旧版启动/导入后的按天自动重排与链条平移入口停用，避免继续改写日期；旧推迟按钮替换为时间设置。

新执行计划不会改变截止；更早截止或更长耗时与现有执行块冲突时，需要先移除/重排该安排再调整。再次自动分析不会覆盖已确认截止和已有安排的耗时。

## 算法与运行边界

纯函数在main/planning/engine.ts：

1. 严格校验本地日期，最多七天。
2. 按星期与生效范围展开课程。
3. 从每天可安排窗口减去课程及已有任务，任务前后预留配置休息，得到空闲区间；不把多个短空档伪装成连续时段。
4. 就绪任务按已确认截止更早、现有优先级更高、ID排序。本阶段没有显式依赖图，不将同批导入等同真实依赖。
5. 连续耗时向上对齐15分钟，在指定每日时段、截止、范围计划窗口和每日任务容量内寻找最早可行块。固定课程不取整移动。
6. 无解返回所需连续分钟、最大可用连续空档和可用容量等实际反馈，不突破截止强排。

main/planning/service.ts负责数据库快照、草案和提交：快照版本为相关任务、课程、计划、设置和时区的摘要；试排只保存草案，不占正式时段。用户确认时检查归属、30分钟有效期、快照版本、当前时间，并独立复核冲突、休息、容量、范围和截止，短事务写计划及事件。

原安排已开始/锁定时不移动。部分任务不能重排时先保留它们的旧块，再重新计算其他任务，避免成功项占用了失败项仍在使用的时间。重复提交同一草案返回已提交结果，不重复插入。

当前为可解释的最早可行贪心基线，未实现偏好评分、显式前置依赖、任务自动拆分或全局最优。无可行结果指在当前保留条件和启发式路径下无可行安排，不声称证明全局无解。

## Agent与内部工具

新增get_calendar、get_free_slots、preview_plan、propose_plan；沿用原生Function Calling与第一阶段的等待/结束机制，不用MCP。

preview_plan要求本轮已查询到的任务ID；支持每日dailyStartMin/dailyEndMin，例如下午12—18点为720—1080。模型可根据用户目标选择查询、试排、阅读未安排原因、改变候选窗口或询问；不能改外部截止或假称已拆分。propose_plan只能引用当前Run自己的真实预览；可信UI确认后提交。

模型读取的时间同时提供deadlineLocal、startLocal/endLocal及当前时区，数据库仍保留标准时间/epoch。真实测试曾将10:00Z误读为本地10点；加入本地可读字段和时区说明后复测通过，避免把精确换算交给模型猜测。

## 验证记录

自动化与真实调用结果以最终命令记录为准。已有覆盖：旧日期迁移、重复迁移、日期/范围校验、区间相减、课程生效、连续空档、截止/容量无解、候选期限确认、截止与执行分离、重复提交、下午窗口、休息、锁定、部分重排失败保留、并发版本、过期、事务回滚、课程冲突、预览归属、生成场景独立约束检查及Agent草案确认。

真实千问新增两条场景：按明日下午课程安排测试报告，确认后保存且截止不变；无法在截止前安排时读取试排失败并说明，不伪造计划。使用合成任务和临时数据库，不对用户个人任务库做实验。

最终检查：`npm run typecheck`、`npm run build`通过；`npm test -- --live`共46项通过（41项隔离库/算法测试，5项真实千问场景，其中2项为本阶段规划场景）。这是本次回归结果，不是稳定成功率或首次通过率。生成场景覆盖12组确定性任务输入，另行检查无课程/任务重叠、容量和截止约束。

回归还暴露原有终态协议的偶发问题：模型连续用普通文字追问。补充respond(mode=question/answer)和一次指定函数的格式转换；模型仍自行选择问或答，Harness只要求结构化输出。真实调用也曾出现多余澄清，不据单次通过宣称所有表达都稳定。关键写入始终需要程序校验和用户确认。

桌面验收使用第一阶段合成v6库的隔离副本，核对自动备份生成、待确认旧日期、任务表单确认截止/耗时、周五课程09:00—10:40的录入。真实Agent将两小时报告安排到次日10:45—12:45；确认保存后，周视图中黄色课程块与蓝色执行块分别显示，任务截止保持次日18:00。实际点击与落库结果一致，演示不包含用户真实日程。

实际工具轨迹：list_tasks→get_calendar→get_free_slots→preview_plan→propose_plan→用户确认→confirmed_plan。关闭重开后，课程、执行块、确认后的截止及对话均保留；新版小时刻度与导航后回到页首也做了原生窗口核对。
