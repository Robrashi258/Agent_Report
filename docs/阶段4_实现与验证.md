# 阶段4：事项录入闭环与共享场景接入

版本：0.2.0-alpha.4；开发分支：feature/planning-agent；日期：2026-11-05。接在阶段3提交5366deb之后。main继续保留0.1。

## 1. 本次完成

1. 顶部默认“助理整理”：输入后进入capture场景，模型自主选择查询记忆、澄清或建立草案。明确事项可以直接出草案；问题回答回到同一Run。保留可明确选择的旧“快速记录”。
2. 独立事项草案：内容、耗时/分组、评分/分类、截止状态、执行范围、纳入开关和备注可修订。模型工具只能准备和提出草案；保存版本后由可信界面确认创建。
3. 批量预览：先按行建立可编辑候选，默认排除明确的称呼/标题；完整原文保留。无法理解的行仍可检查，不自动扔掉。最多60行；30分钟是待核对建议；日期不自动充当硬截止。长行候选明确提示缩短并默认排除，原文不缩短。
4. 受控提交：唯一候选身份、版本检查、事务、来源链接和幂等创建。截止与执行窗口分别保存；确认正式任务不等于已安排时段。确认后可继续交给规划Agent试排，再确认执行块。
5. 共享Harness：工具注册、场景工具白名单、确认处理器从集中分支抽出；运行协议v1、Schema子集和模块边界见[接入契约](共享场景接入契约_v1.md)。不使用MCP，不让模型执行SQL。
6. 模拟作业桥接：提供者返回复习建议和证据，经同一草案确认创建真实taskId，再进入规划。固定测试模块没有真实作业解答/OCR，界面明确标注。
7. 今日最近会话选择器、待确认入口和定向打开草案；完成后的后台追问仍走独立消息，不弹窗、不强行改成当前聊天。

## 2. 怎样体验

更新开发分支后执行npm ci（依赖未变化可略过）、npm run build，再双击仓库start-plan.bat。需Node22与本机依赖；启动器不是独立安装包。已经打开的旧应用需正常退出后重新打开，才能运行新构建。

- 在设置配置支持原生工具调用的模型。顶部选“助理整理”，输入“整理课程笔记，预计45分钟，无硬截止”。核对草案后确认创建，再点“转到今日规划继续试排”。
- 输入“学习第三章”，看模型是否根据已有信息选择澄清；回答后检查同一会话的草案。追问不是固定问卷，真实模型行为可能不同。
- 点“批量预览”，粘贴“@所有人”加两条任务；检查称呼未纳入、原文可展开，修改耗时/截止状态后保存，再确认。关闭前必须保存人工修改。
- 今日助理下展开“模拟作业模块对接验证”，生成固定复习草案；确认后用真实任务ID继续试排。此按钮只用于桥接验收。
- 从“待确认”或“最近对话”回到旧草案；停止运行保留草案，放弃草案保留记录但不建任务。

未配置模型仍可人工批量预览、保存和确认，也可选择旧快速记录；自主录入/继续对话/模型规划会提示先配置，不会冒充模型成功。

## 3. 数据与不变量

数据库迁移v9：agent_runs增加scene；新增task_sources、task_drafts、task_draft_revisions、task_draft_links、review_proposals。沿用迁移前备份和独立Agent数据目录，不自动搬动0.1数据库。已确认记忆/耗时/回顾表沿用阶段3。

输入来源不可变，各次保存保留版本快照；补充回答在Run消息/事件。每Run一草案，正式任务与候选一一关联。确认创建、来源链接和已创建ID列表在同一事务；重复确认返回原ID。手工修改绑定当前版本，旧卡片拒绝覆盖。未确认截止不会被猜成期限，后续试排仍需确认日期语义。确认草案产生的评分/估时不会被旧自动分析覆盖。

默认按行候选是人工检查的起点，不宣称已正确理解任意群通知或识别全部噪声；可继续让模型修订。前置依赖、自动多块拆分、临时课表例外、完整统计、定时主动提醒仍按原后续阶段安排。本阶段修订的是候选草案，不是任意已有任务字段的对话编辑器。

## 4. 验证记录

独立测试使用临时数据库，未使用用户业务库。类型检查、构建和78项隔离回归通过；真实模型回归结果见本节末追加记录。

新增17类测试覆盖：充分/模糊录入与恢复、候选去重、批量原文和称呼排除、长行/数量限制、修订快照与旧版本拒绝、重复确认与来源链接、12项批量交接完整查询（修复默认只返回10项的问题）、未知耗时/截止、时间语义分离、越权字段、写入中断回滚、放弃、场景权限、模块注册、独立场景运行、模拟建议到规划保存。阶段1—3的61项回归仍保留。

真实千问新增3场景：明确事项确认后唯一创建；模糊目标澄清后建草案并修改估时；模拟模块确认后由真实模型调用规划工具并保存计划。测试固定输入不是模型首次成功率评测。

过程中发现并修复：候选编辑组件初始脏状态误判；保存通知引起自己重读；打开新会话保留旧滚动位置和首次加载竞态；模型把确认卡替换成口头确认、把未来7天写成含起止8天。完整真实回归还暴露“实际试排”请求被模型凭课表推断替代、事实回答被后续问题替代、按名称找任务时猜测ID的问题，已补充系统提示和工具描述。提示改进不等于模型行为确定或首次成功率为100%。

Windows界面验收使用独立合成数据窗口：原3项待办；导入3行含@所有人，确认前待办不变；将一个候选30分钟改45分钟，未保存时确认禁用；保存后版本4→5；确认只创建2项，显示真实ID5、6，待办3→5，称呼未入库。关闭/重开仍显示版本5和同一ID；直接只读检查合成库的耗时为45/30分钟，来源链接各一条。模拟模块按钮生成明确标注的固定复习建议，待确认中心能定位回同一Run；切换场景后页面回顶部。未关闭或改动原先已打开的另一窗口及其数据。

最终验证：Node22.16.0；`npm run typecheck`、`npm run build`通过；`npm test -- --live`一次完整执行返回 **89 passed（78项隔离＋11项真实调用）**。模型为千问qwen-plus，调用兼容接口；只发送合成验收数据。此前失败没有删除断言或计入通过数，按上述原因修正后重新跑完整测试；此记录不代表统计学意义的稳定成功率。真实后台决策当次为asked，完成状态保持done，消息唯一。临时验收库及其迁移备份中的凭据已清空；数据库、构建和原始日志均不提交。
